Alta al club de lectura

Objectiu

Aconseguir que el navegador validi el formulari d'alta d'un club de lectura sense escriure ni una línia de JavaScript, només amb els atributs de validació de l'HTML (apartat 2 de la teoria).

Què has de fer

Crea un formulari com el de la demostració (mateixos camps) i fes que el navegador validi aquestes regles:

CampRegles
NomObligatori. Entre 2 i 30 caràcters. Només lletres i espais (pattern).
Correu electrònicObligatori i amb format de correu (Ha de contenir una @).
EdatObligatori. Número enter entre 14 i 99.
Pàgina web o blogOpcional, però si s'omple ha de ser una URL vàlida.
Gènere preferitObligatori: no es pot deixar l'opció «Tria un gènere...».
Telèfon mòbilOpcional, però si s'omple ha de ser exactament 9 dígits que comencin per 6 o 7 (pattern).
Accepto les normesLa casella ha d'estar marcada per poder enviar.

Requisits

  1. Cada camp que tingui regles ha de tenir un title que expliqui quin format s'espera, i un placeholder d'exemple on tingui sentit.
  2. El camp del telèfon mòbil ha d'obrir el teclat numèric en un mòbil (inputmode).
  3. No es pot posar novalidate ni cap <script>.
  4. Un cop validat, el formulari ha de continuar el seu enviament normal (action="#").

Prova-ho

Intenta enviar el formulari buit, amb un correu sense @, amb l'edat 13, amb un nom amb números i amb la casella sense marcar. Comprova que el navegador no l'envia en cap cas.

Així ha de funcionar

Aquest és un formulari de mostra ja acabat. Prova'l i fixa't en el comportament: el teu ha de fer el mateix. Només amb atributs HTML: prova d'enviar-lo buit, amb un correu sense @, amb edat 13...

Punt de partida

Si vols, copia aquest HTML i aquest CSS per no haver d'escriure el formulari des de zero. Desa'ls en una carpeta com a index.html i estils.css. L'HTML no té els type ni les validacions: els comentaris TODO expliquen què ha de complir cada camp i ho has d'afegir tu. El CSS ja està acabat.

  max-width: 480px;

  padding: 0 1rem;
}


/* ===== FORMULARI ===== */

/* Cada camp (etiqueta + control) és un bloc separat de l'anterior. */
.camp {
  margin-top: 1rem;
}

/* L'etiqueta ocupa la seva línia, en negreta, i queda just a sobre del camp. */
label {
  display: block;
  font-weight: 600;
  margin-bottom: 0.25rem;
}

/* Tots els camps (text, número, llista...) ocupen tota l'amplada, amb farciment i vora arrodonida.
   box-sizing: border-box fa que el farciment i la vora no facin el camp més ample que el 100%.
   La casella de selecció s'exclou perquè ha de mantenir la seva mida natural. */
input:not([type="checkbox"]),
select {
  width: 100%;
  box-sizing: border-box;
  padding: 0.5rem;
  font-size: 1rem;
  border: 1px solid #868e96;
  border-radius: 4px;
}

/* L'etiqueta de la casella: text normal (no negreta) i en línia amb la casella. */
label.opcio {
  display: inline;
  font-weight: normal;
}

/* Quan un camp té el focus, es mostra una vora de color blau perquè l'usuari vegi on està escrivint.
   Mai s'ha de treure el focus sense posar-ne un altre: el teclat deixaria de ser usable. */
input:focus,
select:focus {
  outline: 3px solid #74c0fc;
  outline-offset: 1px;
}

/* ESTATS DE VALIDACIÓ
   El navegador activa pseudoclasses segons si el valor d'un camp compleix les seves regles:
   - :invalid / :valid -> s'apliquen des del primer moment. Un camp obligatori buit quedaria en vermell
     abans que l'usuari hagi escrit res, i això molesta.
   - :user-invalid / :user-valid -> el mateix, però només DESPRÉS que l'usuari hagi interactuat amb el camp
     (hi ha escrit, n'ha sortit o ha intentat enviar el formulari). És la que s'ha de fer servir.
   Cada regla pinta una vora gruixuda (2px) del color de l'estat: així no depèn només del color
   (pensant en el daltonisme).

   :not(...) -> exclou els elements que compleixen el que hi ha entre parèntesis.
   input:not([type="checkbox"]) vol dir "tots els input que NO són caselles de selecció".
   S'exclouen perquè una casella amb vora de 2px es veuria malament.
   A més, cada :not(...) compta per a l'especificitat de la regla. Aquí es repeteix el mateix :not(...)
   que a la regla dels camps perquè les dues regles tinguin la mateixa especificitat i, en anar després,
   guanyi aquesta. Si no, la vora grisa del camp guanyaria i no es veuria el vermell. */
input:user-invalid:not([type="checkbox"]),
select:user-invalid {
  border: 2px solid #c92a2a;
}

input:user-valid:not([type="checkbox"]),
select:user-valid {
  border: 2px solid #2b8a3e;
}

Repàs de teoria

Per què importa el type

L'atribut type de l'<input> diu al navegador quin tipus de dada s'espera. Si no se'n posa cap, el camp és de text (type="text") i el navegador accepta qualsevol cosa. Triar-ne el correcte aporta tres coses sense escriure codi:

  • Validació automàtica del format: un type="email" rebutja un valor sense @; un type="number" només admet números.
  • Teclat adequat al mòbil: s'obre el teclat numèric, el del correu (amb @), etc.
  • Controls propis: els números tenen fletxes, les dates un calendari, i les caselles es poden marcar.

Els type d'aquest formulari:

CamptypePer què
NomtextÉs text lliure. El format (només lletres i espais) es comprova amb pattern.
Correu electrònicemailComprova que tingui forma de correu (nom@domini) i mostra el teclat amb @ al mòbil.
EdatnumberNomés admet números i permet min, max i step (que no serveixen en un camp de text).
Pàgina weburlExigeix una adreça completa, amb protocol (https://...).
Telèfon mòbiltext + inputmodeEs fa servir text perquè un number admetria decimals i signes. inputmode="numeric" només canvia el teclat, no valida res: la validació la fa pattern.
NormescheckboxCasella que es marca o no; amb required ha d'estar marcada.

El <select> no porta type. Recorda que type comprova el format, no que el camp estigui omplert: un correu buit és «vàlid» si no té required.

Els estats de validació amb CSS: :user-invalid, :user-valid i :not()

SelectorQuè fa
:user-invalid / :user-validApliquen un estil al camp segons si és vàlid o no, però només després que l'usuari hi hagi interactuat: quan en surt després d'haver-ne canviat el valor o quan intenta enviar el formulari.
:not(...)Exclou el que coincideix amb el que hi ha entre parèntesis. input:not([type="checkbox"]) són «tots els input menys les caselles».

Fixa't que un mateix camp pot tenir una vora per defecte, una altra quan té el focus i una altra quan és invàlid. Quan dues regles afecten la mateixa propietat, guanya la més específica (i, si empaten, la que va després al CSS). Cada :not(...) o pseudoclasse compta per a l'especificitat, i per això la regla de :user-invalid del CSS del punt de partida repeteix el mateix :not(...) que la regla dels camps.
