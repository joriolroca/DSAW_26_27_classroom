Alta al club de lectura (amb l'API de validació)

Objectiu

Fer un formulari d'alta amb 5 camps, validat amb JavaScript. En acabar, hauràs après a:

  • Validar el formulari amb l'API de validació del navegador (checkValidity() i validity), aprofitant els atributs de l'HTML.
  • Fer servir novalidate: el navegador no mostra els seus missatges, els mostres tu.
  • Escriure un missatge d'error propi per a cada cas, segons la regla que falla.
  • Pintar cada camp de verd (correcte) o de vermell (amb error) quan se'n canvia el valor (change).
  • Tornar a validar tots els camps en enviar el formulari i posar el focus al primer erroni.

Regles de validació

Els atributs de validació de l'HTML (required, pattern, min...) ja venen posats al punt de partida: ara se'n treu partit amb JavaScript.

Què has de fer (a script.js)

El punt de partida ja porta el camp «nom» fet com a exemple. Tu has de fer el mateix amb els altres quatre camps.

  1. Agafa els elements. Per a cada camp (#email, #edat, #genere, #normes) i el seu element d'error (#error-email...), amb document.querySelector.
  2. Escriu una funció per camp: validarEmail, validarEdat, validarGenere i validarNormes, com la validarNom de l'exemple. Ha de retornar true si el camp és correcte i false si no.
  3. Comprova si el camp és vàlid amb camp.checkValidity().
  4. Si és vàlid (verd): escriu «✔ Correcte» a l'element d'error i posa-li la classe ok; al camp, treu-li invalid i posa-li valid (amb classList).
  5. Si no és vàlid, escull el missatge: comprova una a una les propietats de camp.validity (valueMissing, typeMismatch, rangeUnderflow, rangeOverflow, stepMismatch...) amb if / else if, una per cada missatge de la taula.
  6. Pinta l'error (vermell): escriu el missatge a l'element d'error i treu-li la classe ok; al camp, treu-li valid i posa-li invalid.
  7. Valida en canviar el camp: afegeix a cada camp un addEventListener("change", ...) amb la seva funció.
  8. Amplia el submit: l'exemple del nom ja fa event.preventDefault() i valida només el nom. Fes-hi que es validin els 5 camps.
  9. Crida les 5 funcions i guarda què retorna cadascuna (const emailOk = validarEmail();...). S'han de cridar totes, també si alguna falla, perquè es pintin tots els camps.
  10. Posa el focus al primer camp que falla, seguint l'ordre del formulari (camp.focus()), i atura't amb return. No esborris el que l'usuari ha escrit.
  11. Si tot és correcte: mostra un missatge de benvinguda a #resultat.
  12. Neteja el formulari: form.reset(), i treu les classes i els missatges dels 5 camps.

Prova-ho

Escriu un valor correcte en un camp i surt (es posa verd); escriu-ne un d'incorrecte i surt-ne (es posa vermell). Envia el formulari buit, amb un correu sense @, amb l'edat 13, amb un nom amb números i amb la casella sense marcar.

Fixa-t'hi: change només es dispara si el valor ha canviat quan l'usuari surt del camp: si entra en un camp i en surt sense escriure res, no passa res. Per això en submit es validen tots els camps. I si l'usuari corregeix un camp, el vermell continua fins que el canvia i en surt, o fins a l'enviament.

Així ha de funcionar

Aquest és un formulari de mostra ja acabat. Prova'l i fixa't en el comportament: el teu ha de fer el mateix. Envia'l buit, amb un correu sense @, amb edat 13... i fixa't en els missatges i en on va el focus.

script.js
const form = document.querySelector("#form-alta");
const resultat = document.querySelector("#resultat");


// ===== EXEMPLE: EL CAMP «NOM» =====
// Agafem el camp i l'element on escriurem el seu error
const nom = document.querySelector("#nom");
const errorNom = document.querySelector("#error-nom");

// Comprova el nom i el pinta de verd o de vermell. Retorna true si és correcte.
function validarNom() {
  // checkValidity() és true si el camp compleix totes les seves regles (required, pattern...)
  if (nom.checkValidity()) {
    errorNom.textContent = "✔ Correcte";
    errorNom.classList.add("ok");               // text verd
    nom.classList.remove("invalid");
    nom.classList.add("valid");                 // vora verda
    return true;
  }

  // Si no és vàlid, validity ens diu QUINA regla falla. Es mira cada cas per separat:
  // una propietat de validity per a cada missatge.
  if (nom.validity.valueMissing) {
    errorNom.textContent = "El nom és obligatori";
  } else if (nom.validity.patternMismatch) {
    errorNom.textContent = "Només lletres i espais (de 2 a 30)";
  }
  errorNom.classList.remove("ok");              // text vermell
  nom.classList.remove("valid");
  nom.classList.add("invalid");                 // vora vermella
  return false;
}

// Quan l'usuari canvia el valor del camp (i en surt), es valida
nom.addEventListener("change", validarNom);


// Quan s'envia el formulari, es valida el nom (encara que l'usuari no l'hagi canviat mai: llavors "change" no s'ha disparat)
form.addEventListener("submit", (event) => {
  event.preventDefault();          // evita que la pàgina es recarregui
  resultat.textContent = "";

  const nomOk = validarNom();      // valida el nom i el pinta; guardem si és correcte

  if (!nomOk) {                    // si el nom no és correcte...
    nom.focus();                   // ...posem el focus al camp perquè el corregeixi...
    return;                        // ...i aturem l'enviament (no s'esborra res del que ha escrit)
  }

  // Si arribem aquí, el nom és correcte
});

Repàs de teoria

L'API de validació: què li pots preguntar a un camp

Encara que el formulari porti novalidate, el navegador continua calculant si cada camp és vàlid segons els seus atributs (required, type, pattern, min...). El que fa novalidate és només no mostrar els seus missatges ni bloquejar l'enviament: d'això ara te n'ocupes tu.

QuèPer a què serveix
camp.checkValidity()Retorna true si el camp compleix totes les seves regles i false si no.
camp.validityDiu quina regla falla (taula de sota).
Propietat de validityÉs true quan...
valueMissingel camp és required i està buit (o la casella desmarcada).
typeMismatchel valor no té el format del type (per exemple, un correu sense @).
patternMismatchno compleix el pattern.
rangeUnderflow / rangeOverflowés menor que min o major que max.

Un camp pot fallar per més d'una regla alhora. Per això els if es posen en ordre i es mostra només el primer error que es troba.

Quan es valida: change i submit

EsdevenimentQuan es produeixÚs en aquesta activitat
changeQuan el valor del camp ha canviat i l'usuari el confirma: en un camp de text, en sortir-ne; en un select o una casella, en triar-ho.Valida el camp tan bon punt l'usuari acaba amb ell. No es dispara si el camp no ha canviat.
submitEn enviar el formulari, amb el botó o amb Enter.Valida tots els camps i porta el focus al primer erroni. Sempre s'ha de fer: l'usuari pot prémer «Apuntar-me» sense haver passat per tots els camps.

El flux en enviar

  1. L'usuari prem el botó (o Enter) i es produeix l'esdeveniment submit.
  2. event.preventDefault() impedeix que la pàgina es recarregui; així tu pots validar abans d'enviar res.
  3. Per a cada camp, la seva funció crida checkValidity() → si és false, es llegeix validity per saber el motiu i es mostra el missatge en vermell; si és true, es pinta de verd.
  4. Si hi ha errors, camp.focus() al primer; si no, es dona la benvinguda i es fa form.reset().

El CSS del punt de partida

A l'activitat 1 el navegador decidia quan un camp tenia l'estil d'invàlid (:user-invalid). Aquí ho decideix JavaScript, que posa les classes .invalid (vermell) i .valid (verd).
